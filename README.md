# depth-tools — Карта глубины из фото (Depth Anything V2, Depth Pro + UI)

Локальные инструменты для генерации карт глубины из фото и совмещений, без облака.

## Компоненты

- `depth_from_photo.py` — простой конвейер: фото -> карта глубины, оверлей, DoF, сравнение "цвет + глубина". Настройки вверху файла.
- `depth_ui.py` — графический интерфейс (tkinter): выбор фото через системный диалог (zenity на Linux, нативный на Windows), выбор модели (Small/Base/Large/MiDaS/ZoeDepth/Indoor/Outdoor-варианты и Depth Pro), слайдеры, одно окно предпросмотра с переключением типа (глубина / цветная карта EXR / нормали EXR / цветное фото; «Цветная карта EXR» и «Нормали EXR» появляются, только когда включены их файлы в «Результатах») и флажком «Предыдущий», глубокие форматы (16-бит PNG, float TIFF, EXR).
- `_depth_pro_infer.py` — отдельный процесс для Depth Pro: PyTorch и ~1 ГБ весов не висят в памяти окна после обработки.
- `depth_tune.py` — интерактивный подбор настроек через вопросы.
- `depth_gen.py` — процедурный рендер сцены (сферы) с точной глубиной, без нейросети.

## Установка за один клик

### Windows

1. Скачайте репозиторий (Code → Download ZIP) и распакуйте.
2. Двойной клик по **`depth_ui.bat`** — он сам:
   - установит Python 3, если его нет;
   - создаст виртуальное окружение и поставит зависимости;
   - скачает модель (~99 МБ);
   - создаст ярлык «Карта глубины» на рабочем столе;
   - запустит приложение.

> Если что-то пошло не так — рядом с `depth_ui.bat` появится файл **`depth_ui.log`**
> с пошаговым журналом установки и текстом ошибки. Пришлите его содержимое.

### Linux

```bash
git clone https://github.com/Dlicak/depth-tools
cd depth-tools
chmod +x install.sh
./install.sh
```

`install.sh` сам поставит python3-venv (через sudo), окружение, зависимости, скачает модель и запустит приложение.

## Модель

Комбобокс **«Модель»**: Small (~99 МБ, быстро) / Base (~390 МБ, детальнее) / Large (~1.3 ГБ, максимум деталей), а также MiDaS, ZoeDepth, метрические Indoor/Outdoor-варианты Base/Large и **Depth Pro**. Нужная модель скачивается автоматически при первом запуске. Каталог данных: `~/Z-depth` / `%USERPROFILE%\Z-depth`.

Все пути на обеих ОС портативные (см. «Пути» ниже).

## Depth Pro

**Depth Pro** (`apple/DepthPro-hf`) — метрическая глубина с оценкой фокусного расстояния; на границах объектов заметно резче, чем Depth Anything V2. В отличие от остальных моделей, она работает не через onnxruntime, а через PyTorch:

- при первом выборе в списке приложение спрашивает разрешение и скачивает `torch` (CPU-сборка, ~250 МБ), `transformers` (~50 МБ) и веса (~1,9 ГБ) в `Z-depth/DepthPro`; прогресс виден прямо в кнопке «Применить», повторный запуск ничего не качает;
- обработка идёт в отдельном процессе (`_depth_pro_infer.py`), поэтому после завершения память освобождается;
- на ноутбуке без видеокарты это **десятки секунд — минута** на фото; нужно ~6 ГБ свободной ОЗУ. Вход у модели всегда 1536×1536, как в оригинале, поэтому «Множитель входа» на неё не влияет — разрешение результата задаёт «Выход»;
- выход переводится в привычную шкалу 0–1 (обратная глубина, 1.0 = близко), поэтому «Глубина от/до %», гамма и контраст работают как обычно;
- предсказанный угол обзора подставляется в PLY/GLB вместо зашитых 60° — облако точек получается пропорциональным;
- журналы: `Z-depth/depth_pro_install.log` (установка) и `Z-depth/depth_pro_run.log` (запуск модели).

Лицензия весов — Apple Sample Code License (`apple-amlr`), не MIT: для коммерческого использования прочитайте условия в репозитории модели. Скачивание выполняет само приложение, веса в репозиторий не входят.

## Результаты

Файлы сохраняются в каталоге данных (`~/Z-depth` / `%USERPROFILE%\Z-depth`): `photo_src.exr` (исходное фото в linear, пишется всегда) и `photo_colormap.png` (цветная карта Inferno); остальное — по галочкам:

| Галочка | Файл | Формат |
|---|---|---|
| Глубина EXR | `photo_depth.exr` | float32 EXR, глубина 0–1 без гаммы |
| 16-бит PNG | `photo_depth_16.png` | PNG 16-бит, серая шкала |
| 32-бит TIFF | `photo_depth_32.tif` | TIFF float32 |
| Цветная карта EXR | `photo_colormap.exr` | RGB (linear) + альфа = глубина |
| Нормали EXR | `photo_normal.exr` | RGB-нормали, 0.5 = «плоско» |
| XYZ-облако PLY / Модель GLB | `photo_points.ply` / `.glb` | точки с цветом |

16-битная цветная карта (`photo_colormap_16.png`) пишется вместе с галочкой «16-бит PNG».

**XYZ-облако (PLY)** и **Модель 3D (GLB)** строятся из карты глубины: пиксель = вершина, цвет берётся из фото. Ось Z — глубина (1.0 у камеры, ~0.05 вдали), треугольники ориентированы «лицом» к камере, поэтому в Blender и просмотрщиках модель не вывернута. Угол обзора зашит (60°, как у обычной камеры) — отдельных ползунков FOV и масштаба больше нет. PLY — текстовый, с гранями и цветом; GLB — одна сетка с нормалями и vertex color.

При включённой галочке **«Гибрид»** (вторая цепочка рендера) промежуточные рендеры тоже сохраняются отдельно: `photo_colormap_1.png/.exr` и `photo_depth_1.png`, а результат второго рендера — `photo_colormap_2.png/.exr` и `photo_depth_2.png`; финал — смесь цветов первого и второго рендера 50/50.

## Предупреждение про ОЗУ

**«Множитель входа»** — разрешение, на котором работает модель: `200 px × множитель` по длинной стороне. `6` → ~1200 px (обычный режим для фото 1000–2000 px), `10` → ~2000 px (детальнее, но заметно больше ОЗУ), `1` → 200 px (быстро, грубо). Выше 4x от размера исходного фото вход не растягивается. Реальное значение показано рядом с ползунком (`6x → 1200 px`). Если ОЗУ всё же закончилось — обработка автоматически остановится с сообщением.

## Сжать оригинал до

Опция **«Сжать оригинал до»** уменьшает исходное фото в 1–4 раза **до** модели: `1x` — оригинал, `2x` — половина стороны, `3x` — треть, `4x` — четверть. Разрешение входа от этого не зависит (оно задаётся множителем), зато падает разрешение выхода и расход ОЗУ.

| Сжать оригинал до | Размер фото | Выход 1x при множителе 6 |
|---|---|---|
| 1x | 1920×2560 | 1920×2560 |
| 2x | 960×1280 | 960×1280 |
| 3x | 640×853 | 640×853 |
| 4x | 480×640 | 480×640 |

«Размер выхода» считается от сжатого размера: например, сжатие 2x + выход 1x дадут карту 960×1280.

## Слайдеры глубины

**«Глубина от %»** и **«Глубина до %»** — это проценты **расстояния от камеры**: `0%` — ближайшее к камере, `100%` — самое далёкое. Всё, что ближе «от» и дальше «до», срезается, а оставшийся диапазон растягивается на всю карту. То есть «от 20%» отрезает передний план, «до 70%» — фон.

**«Сглаживание»** — сила edge-aware фильтра (guided filter по фото): `0` — выключено, `100` — максимум. Увеличение ползунка всегда уменьшает шум и детализацию, но сохраняет границы объектов.

**«Гамма глубины»** — перераспределение полутонов: больше `1` — светлее ближняя часть, меньше `1` — темнее.

## Предпросмотр

В правой карточке четыре типа: **Глубина**, **Цветная карта**, **Нормаль**, **Цветное фото**. Переключаются кнопками или колесом мыши в любом месте карточки предпросмотра (включая кнопки типов и флажок «Предыдущий»): вниз — следующий тип, вверх — предыдущий. «Нормаль» показывает ту же карту нормалей, что сохраняется в `photo_normal.exr` — по ней сразу видно, где наклон поверхности слишком резкий. Флажок **«Предыдущий»** слева от кнопок сравнивает с прошлым результатом. Размер картинки показан в углу карточки.

Колесо мыши над любым ползунком двигает его значение (влево/вправо), а не прокручивает панель.

Окно тёмное: слева карточка настроек (на низком экране она прокручивается), справа предпросмотр. Кнопка **«Применить»** занимает всю ширину окна: пока идёт обработка, на ней же показывается процент готовности — отдельного индикатора нет, а повторные нажатия во время работы игнорируются. Кнопка **«Открыть папку»** стоит в заголовке раздела «ФОТО», рядом с выбором снимка.

## EXR-файлы

- `photo_depth.exr` (флажок «Глубина EXR») — относительная глубина 0–1 во всех каналах, float32, без гаммы: ровно те числа, что видит Blender
- `photo_colormap.exr` (флажок «Цветная карта EXR») — RGB = цветная карта палитры (linear), **альфа-канал = глубина 0–1**. В Blender геонодах берите глубину из выхода Alpha текстуры, цвет точек — из Color
- `photo_normal.exr` (флажок «Нормали EXR») — нормали в tangent space: R = X, G = Y, B = Z (плоскость «лицом к камере» = 0.5, 0.5, 1.0)

## Сцена `scenes/cloud2.blend` (геоноды)

Готовая Blender-сцена с облаком точек из карты глубины. Нода-группа **«Photo Cloud»**:

- вход **Scale** — крутилка масштаба 2D (по ширине фото);
- размер сетки берётся автоматически из исходного изображения (нода Image Info: ширина/высота текстуры, работает и с EXR-картой глубины, и с обычным фото);
- `Res U`/`Res V` — количество точек по сторонам, `Height` — вертикальная амплитуда, `Radius` — размер точки, `To Min`/`To Max` — границы высоты рельефа.

> **Совместимость версий.** `cloud2.blend` — файл формата Blender 5.x и в старых версиях (3.x) не открывается. Для Blender **3.6** сделан отдельный файл — см. ниже.

## Сцена `scenes/cloud2_3.6.blend` (Blender 3.6)

Тот же набор геонод (группы **«Photo Cloud»**, **«Cloud to Mesh»**, **«MeshInferno»**, цвет по Inferno через атрибут `DCol`), но собран в формате Blender 3.6 и предназначен для версии **3.6.x**. Открывается обычным «File → Open». Файл `scenes/cloud2.blend` для Blender 5.x при этом не изменяется.

- текстуры привязаны к `scenes/textures/photo_colormap_rgba16.png` (цвет + **альфа = глубина**, сконвертирован из `photo_colormap.exr`, т.к. EXR эта сборка Blender 3.6 не читает) и `photo_normal.png`. Цвет точек и глубина рельефа берутся из одного файла, как в Blender 5.x (`photo_src.png`/`photo_depth.png` в этой сцене не используются — глубина именно в альфа-канале `photo_colormap.exr`);
- если карта глубины сменится — замените эти PNG (или проставьте свои изображения во входах группы «Photo Cloud» у объекта Photo Cloud);
- `Res U`/`Res V` теперь задают **целевое число точек** (их произведение), а соотношение сторон сетки автоматически подгоняется под пропорции исходного фото: сетка всегда ровно покрывает фото без растяжения. Фактические размера рассчитаны нодами (Image Info + квадратный корень) по `photo_depth.png`;
- «Cloud to Mesh» не имеет своих значений сетки — она читает фактические `Res U`/`Res V` из атрибутов облака точек (`ResU`/`ResV`), поэтому меш всегда синхронен с облаком.

## Пути (портативно, без хардкода)

Все пути определяются автоматически и настраиваются через переменные окружения:

| Переменная | Linux | Windows | Назначение |
|---|---|---|---|
| `DEPTH_TOOLS_HOME` | `~/Z-depth` | `%USERPROFILE%\Z-depth` | Каталог данных (настройки, результаты) |
| `DEPTH_TOOLS_MODELS` | `$DEPTH_TOOLS_HOME` | `%DEPTH_TOOLS_HOME%` | Где искать ONNX-модели |
| `DEPTH_TOOLS_SRC` | свежий файл в `~/Downloads` | свежий файл в `%USERPROFILE%\Downloads` | Исходное фото по умолчанию |

Каталог данных создаётся автоматически. Модель ищется в каталоге моделей и рядом со скриптом; если её нет — понятная ошибка вместо падения.
